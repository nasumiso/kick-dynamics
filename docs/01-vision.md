# 01 ビジョン

> 状態：初版（2026-10-18）。本書はプロジェクトの目的・優先順位・非目標・名称体系の正本です。

## 1. 目的

足とボールの接触条件からキックの結果を物理的に計算し、3D で観察・検証できるブラウザアプリケーション（KickDynamics Lab）を作る。その物理計算部分（KickDynamics Core）を描画やゲームから独立した基盤として育て、将来は同じ Core を使ったゲーム（候補名 FootBallistics）へ発展させる可能性を残す。

## 2. 背景と問題意識

サッカーを題材にしたゲームやツールでは、キックの強さ・方向・カーブ量のような「結果に近い量」を入力し、軌道を演出的に生成する設計がよく見られる（一般的な傾向としての認識であり、特定作品を調査した結果ではない）。

本プロジェクトはその逆に、「足がボールのどこに、どの向き・速度・姿勢で当たったか」という**原因側**を入力とし、

1. 接触モデルによってボールの並進初速度と角速度を求め、
2. 飛翔・接地モデルによってその後の軌道を求める、

という因果の連鎖をそのまま計算・可視化する。キックの種類（インステップ、インサイド、インフロント、アウトサイド等）による違いも、名前ごとの補正ではなく、足の形状・姿勢・衝突条件の違いから生じる**物理的結果**として再現することを長期目標とする。

ショット条件を直感的に指定して結果を観察する体験として、『みんなのGOLF』のショット入力画面のような分かりやすさを参考にする。ただし具体的な UI は未確定であり、商用作品の画面は複製しない。

## 3. 想定ユーザーと利用シナリオ

- 主なユーザー：開発者本人（物理モデルの検証と探索）
- 将来のユーザー：サッカーやスポーツ物理に関心のある人、ゲームのプレイヤー

| ID | シナリオ | 想定 Phase |
|---|---|---|
| S-1 | 条件探索：接触点を少しずつずらし、スピンと曲がりの変化を観察する | 1〜 |
| S-2 | モデル比較：同一条件で「有限質量の足」と「無限質量の動く壁」の結果を比べる | 1〜 |
| S-3 | 検証：解析解・保存則のテストや、実測データとの比較でモデルの妥当性を確認する | 1〜 |
| S-4 | 説明・学習：反発係数やマグヌス効果の影響を可視化して理解する（副次的） | 1〜 |
| S-5 | 接触現象の観察：接触時間・力の時間変化・変形を観察する | 2〜 |
| S-6 | ゲーム：同じ Core を使ってフリーキック等を遊ぶ | 5 |

## 4. 差別化方針

- **因果の向き**：原因（接触条件）から結果（初速・回転・軌道）を計算する。
- **透明性**：モデルの仮定、パラメータの出典と確からしさを文書と UI の両方で公開する。
- **検証可能性**：Core を単体でテストでき、解析解・保存則・収束試験を備える（[06-validation.md](06-validation.md)）。
- **段階的なモデル進化**：瞬間点接触 → 有限時間接触 → 面接触 → 関節拘束へ、Core の API 境界を保ったまま差し替える（[03-roadmap.md](03-roadmap.md)）。
- 類似事例は調査候補として扱い、機能比較は一次情報を確認してから行う（[research](research/references-and-open-questions.md)）。

## 5. 優先順位

初期段階（少なくとも Phase 1〜4）の優先順位：

1. 物理的妥当性（モデルの仮定が明示され、実装が数式どおりであること）
2. 検証可能性（自動テスト、診断値、データ出力）
3. 観察のしやすさ（可視化、測定値表示、リプレイ）
4. 操作の直感性
5. ゲーム的な楽しさ・演出

ゲーム化（Phase 5）で操作性のための調整が必要になった場合も、調整は Core の外側（入力のマッピング、カメラ、演出、ルール）で行い、Core の物理計算に恣意的な補正を加えない。補正をどう扱うかは Phase 5 の前に ADR で決める（[OQ-22](research/references-and-open-questions.md)）。

## 6. 段階ごとの到達像（概要）

| Phase | 到達像 | 主張してよいこと |
|---|---|---|
| 1 | 点接触剛体モデルで、接触条件 → 初速・回転 → 軌道の因果を観察できる | モデルの数式どおりに計算されていること（実装検証済みの範囲） |
| 2 | 接触時間・接触力の時間変化・簡易変形を観察できる | 同上 ＋ 実測照合を行った項目はその結果 |
| 3 | 足形状と面接触から、キック種別の違いを入力条件の違いとして再現する | 同上 |
| 4 | 関節拘束・詳細空力を含め、実測と定量比較する | 比較結果と不確かさ |
| 5 | 同じ Core を基盤にしたゲーム | — |

詳細は [03-roadmap.md](03-roadmap.md) を参照。

## 7. 非目標

### 7.1 全体の非目標

- 商用作品の画面・UI の複製
- キック種別の名前に応じた恣意的な曲がり・スピン補正
- 軌道（飛距離・カーブ量・打ち出し角）を先に指定することを主操作とすること（目標軌道から条件を探す逆問題を補助機能として扱う可能性は未決定）
- サーバー側での計算、オンライン機能（現時点では対象外）
- 選手の全身運動・アニメーションの物理的生成（現時点では対象外）

### 7.2 Phase 1 の非目標

- 実際のキックを高精度に再現しているという主張
- 接触時間、変形、接触面積・圧力分布、接触力の時間履歴
- 足形状に基づく面接触、関節拘束
- スマホ最適化
- ゲームモード、スコア、ルール
- 無回転ボールなどの高度な空力

## 8. 名称体系

| 用途 | 名称 | 状態 | 備考 |
|---|---|---|---|
| プロジェクト全体 | **KickDynamics** | 採用 | リポジトリ名 `kick-dynamics`。タグライン候補：*The Physics Behind Every Kick.* |
| 物理計算エンジン | KickDynamics Core | 仮称 | `packages/physics-core/`。npm パッケージ名は未決定 |
| ブラウザ上の物理シミュレータ | KickDynamics Lab | 仮称 | `apps/web/`。Phase 1〜4 の主な成果物 |
| 将来のゲーム | FootBallistics | 有力候補 | Football × Ballistics。タグライン候補：*Master the Physics. Master the Kick.* |

- **FootBallistics の商標や既存作品との重複は未確認**であり、公開前に確認する（[OQ-24](research/references-and-open-questions.md)）。確認が済むまで、文書・コード・公開物でこの名称を確定名として扱わない。
- 将来ゲームを複数開発する場合も、KickDynamics Core を共通基盤として利用する想定。
- ゲームのコンセプト候補は「物理を理解するほどキックが上手くなるゲーム」。接触点の調整でカーブをかける、インステップで強いシュートを打つ、インフロントで壁を越えるフリーキックを狙う、といった遊び方は、**Core の物理計算の結果として現れること**を前提とし、キック種別ごとのゲーム的補正で作らない（§5、[AGENTS.md](../AGENTS.md)）。
- コード上の識別子（パッケージ名・ディレクトリ名）に仮称・候補名を埋め込むかどうかは未決定。現時点のディレクトリ名は機能名（`physics-core`、`web`）とする。
