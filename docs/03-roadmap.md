## 1. 方針

- 進捗を **物理モデルの成熟度（PM）** と **機能 UI の成熟度（UM）** の 2 軸で管理する。両者は独立に進めてよく、一方の進捗で他方の成熟を主張しない。
- 各モデルには **検証状態** を付ける（§2.3）。「実装した」ことと「実物を再現している」ことを区別する。
- Phase 1 は KickDynamics Lab の MVP。Phase 5 で FootBallistics（候補名）などのゲームへ展開する。

## 5. Phase 2 と Phase 3 の順序について

接触の変形（Phase 2）と面接触（Phase 3）は技術的に相互依存する。例えば、面接触の接触領域は変形量に依存し、変形モデルは接触領域の形状に依存する。**決定（2026-11-15、人間、[ADR-0009](decisions/0009-plan-after-v1.md)）：案 A**。Phase 2 の範囲は点接触のばねと脚のモデルまでとし、接触領域を持つモデルは Phase 3 に残す。Phase 2 の前に、空力の更新（A1、§3）を行う。

- 案 A：Phase 2（球の簡易変形 ＋ 点接触近似の時間発展）を先に行い、その後に面接触へ拡張する。
- 案 B：足形状と剛体面接触（瞬間）を先に行い、その後に時間発展・変形を加える。
- 案 C：簡易な時間発展と簡易な面接触を同時に導入する。

判断材料：実装難度、検証方法の有無（実測データの入手性）、Phase 1 で見つかった限界、V1 で記録した Phase 1 モデルと文献値のずれ（[V1 検証レポート](reports/v1-validation-report.md) §10）。案 B は、変形がなければ面接触にならないため選ばない。案 C は一度に検証する範囲が大きい。接触領域は、回転の実測（VAL-02）がなく改善を確かめられないため、Phase 2 に含めない。

## 8. 文献による妥当性確認の段階（V1、仮称）

> 状態：**完了（2026-11-15）**。結果は [V1 検証レポート](reports/v1-validation-report.md)、結果にもとづく判断は [ADR-0009](decisions/0009-plan-after-v1.md)。範囲と受入条件の正本は [specs/002-literature-validation/spec.md](../specs/002-literature-validation/spec.md)。

- **目的**：Phase 1 のモデルの出力が、公開されている実測値からどれだけずれているかを記録する。次にどのモデルを精密化するか（Phase 2 / 3 の順序、§5。脚のモデルを Phase 4 より前に出すか）を、根拠で選べるようにする。
- **背景**（[Phase 1 レビュー](reports/phase1-review.md)）：Phase 1 は VAL をすべて未実施で締めた。モデルの精密化を先に進めると、精密化が現実との一致を良くしたかを判定できない。
- **範囲（暫定）**：
  - 自前の計測はしない。文献・公開データだけを使う（[OQ-14](research/references-and-open-questions.md)）。
  - 文献は一次情報で確認したものだけを使い、確認した範囲を research §2 に記録する。
  - Core のモデルの式は変えない。パラメータの値を文献値へ置き換えるかは、項目ごとに人間が判断する（置き換える場合は 05 §10.2 と `MODEL_VERSION` を更新する）。
  - 対象の候補：VAL-01（球速 / 足速）、VAL-02（回転）、VAL-04（軌道）、VAL-10（空力係数）。Phase 2 の目標値になる接触時間・接触力・変形（D-04〜D-06）は、文献値の収集だけを行う。対象の確定は仕様で行う。
- **完了条件（暫定）**：
  1. 対象の各 VAL 項目について、比較の条件・出典・結果・不確かさを検証レポートに記録した。比べられなかった項目は、理由を記録した（[06 §5](06-validation.md)）。
  2. 実測との比較の許容誤差（TOL-D）と、「精巧さ」を測る対象量を決めた。決められなければ、未決定として理由を記録した。
  3. §5 の順序を決めた（ADR）。
- **主張してよいこと**：比較した項目の結果と不確かさだけ。一致しなかった項目を、係数の調整で一致させたことにしない（同定に使ったデータと検証に使ったデータを分ける、06 §5）。
