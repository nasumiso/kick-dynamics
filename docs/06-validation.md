# 06 検証と品質

> 状態：初版（2026-10-18）。本書は検証項目 ID（VER / VAL）・許容誤差の扱い・検証状態の正本です。検証の対象となる数式は [05-physics-model.md](05-physics-model.md) を参照します。
> **現時点で実施済みの検証はありません。**

## 1. 検証の 2 つの区別

| 区別 | 問い | ID | 手段 |
|---|---|---|---|
| 数理・実装検証（Verification） | 計算コードは数式・モデルのとおりに動いているか | `VER-*` | 解析解、保存則、対称性、極限、収束試験、単位・座標系の確認 |
| 現実との妥当性確認（Validation） | モデルは実物のキックを再現しているか | `VAL-*` | 実測データとの比較 |

VER に合格しても、モデルが実物を再現していることにはならない。文書・UI・報告ではこの 2 つを混同しない。

これらに加えて、重要な物理機能については、実装とは独立に導出した結果との照合（独立検証、`IV-*`）を行う（§9）。独立検証は VER を置き換えるものではなく、VER の期待値や仕様そのものの誤りを見つけるための補助である。

## 2. 検証状態の表記

各モデル・各項目の状態は [03 §2.3](03-roadmap.md) の区分（未検証／実装検証済み／実測照合済み）で表す。VAL で実測と比較した場合は、一致したかどうかとは別に、比較条件・データの出典・不確かさを記録する。実測データを収集していない項目は「未検証」と書く。

## 3. 許容誤差の扱い（未決定、[OQ-13](research/references-and-open-questions.md)）

根拠のない段階で数値を決め打ちしない。誤差の種類ごとに決め方の方針だけを定め、数値は該当マイルストーンで決める。

| 区分 | 対象 | 方針 | 数値 |
|---|---|---|---|
| TOL-A | 代数的な恒等式・保存則・閉形式との比較（丸め誤差のみが生じるもの） | 倍精度の丸め誤差の大きさと演算の規模から決める。相対誤差と絶対誤差を併用し、$\lvert a-b\rvert \le \text{abs} + \text{rel}\,\lvert b\rvert$ で判定する | **仮置き**：rel = abs = $10^{-12}$（機械イプシロン約 $2.2\times10^{-16}$ × 演算規模 × 余裕。大きさ 1 程度の量を想定。`packages/physics-core/test/tolerance.ts`、T1.1-04） |
| TOL-B | 時間積分を含む比較 | 絶対値よりも**収束次数**で評価する：刻みを半分にしたとき、誤差が積分法の理論次数 $p$ に応じて約 $2^p$ 分の 1 になること | 判定幅は未決定（M1.2）。**仮置き**：観測した収束次数が理論次数 $p$ から ±0.5 以内（`packages/physics-core/test/flight/drag.test.ts`、T1.2-03） |
| TOL-C | イベント検出（接地時刻など） | 求根の打ち切り条件と時間刻みから決める | 未決定（M1.2） |
| TOL-D | 実測との比較 | 測定の不確かさとモデルの想定する精度から決める | 未決定（データ入手後） |

テストで仮の値を使う場合は、テストコードと本書の両方に「仮置き」と明記する。

| 初速 (m/s) | Δt = 0.06 → 0.03 | 0.03 → 0.015 | 0.015 → 0.0075 | 0.0075 → 0.00375 | それより細かい刻み |
|---|---|---|---|---|---|
| (25, 10, −3)、1.5 s | 4.02 | 4.01 | 4.01 | 3.99 | 丸め誤差（位置で約 $10^{-13}$ m）に達し、次数が下がる |

| 初速 (m/s) | Δt = 0.064 → 0.032 | 0.032 → 0.016 | 0.016 → 0.008 | 0.008 → 0.004 | 0.004 → 0.002 |
|---|---|---|---|---|---|
| (33, 12, 0)、1.6 s | 4.03 | 4.02 | 4.01 | 4.00 | 3.95 |

- 観測した次数は理論次数 4 と整合する。Δt = 0.0075〜0.008 s での位置の誤差は約 $10^{-10}$ m。
- 自動テストは、丸め誤差の影響を避けて Δt = 0.04〜0.005 s で次数を判定する（TOL-B の判定幅は仮置き）。
- マグヌス力・回転減衰を含む条件での収束は、それぞれ VER-F05・F11・F13 で確かめる。

**縮退判定の閾値**：VER-F02〜F13 のテストは、05 §10.2 の仮置きの値（P-21 $\varepsilon$、P-23 $\varepsilon_v$、P-24 $\varepsilon_\omega$）を使う（`packages/physics-core/test/flight/fixtures.ts`）。VER-F06 は、$\boldsymbol\omega \parallel \mathbf v_r$ で外積に丸め誤差が残る場合も $\varepsilon$ によって $\mathbf F_M = \mathbf 0$ になることを含めて確かめる（T1.2-05）。05 §7.5 (c) の縮退（$\lvert\boldsymbol\omega\rvert \le \varepsilon_\omega$、$\lvert\mathbf v_r\rvert \le \varepsilon_v$）は T1.2-06 で確かめる。

**VER-F11・F13 の記録**（T1.2-06）：姿勢（$\lvert\boldsymbol\omega\rvert \approx 19$ rad/s、1 s、Δt = 0.02〜0.0025 s）と線形の回転減衰（$c_\omega/I_B \approx 1$ s⁻¹、2 s、Δt = 0.08〜0.01 s）の誤差は、いずれも Δt を半分にすると約 1/16 になる（観測次数約 4）。各ステップの後に四元数を正規化しても 4 次の収束は保たれる。

## 7. テストの実装方針

- Core のテストは Vitest（候補）で、Node 上で実行する。
- テスト名に VER ID を含める（例：`VER-C01: 1 次元衝突（無限質量）`）。ID とテストの対応を検索できるようにする。
- 前提（$e$、$\mu$、ON/OFF した力項、座標系）をテストごとに明示する。
- ランダムな入力に対して保存則などの性質を確かめるテスト（プロパティベーステスト）は有用な候補だが、専用ライブラリの導入は依存の追加にあたるため承認後に判断する。固定の疑似乱数で入力を生成する方法でも代替できる。
- 入力と期待出力の組（ゴールデンデータ）を保存し、回帰テストと将来の別実装（WASM 等）の検証に使う（[04 §9](04-architecture.md)）。ゴールデンデータの期待値は「実装の過去の出力」であり、物理的な正しさの根拠ではないことを明記する。

## 9. 独立検証ワークフロー

物理計算コアの重要な機能について、実装とは独立に導出した結果と実装を照合する手順を定める。本節が手順の正本であり、他の文書は本節を参照する。

### 9.1 役割

| 担当 | 役割 |
|---|---|
| 人間（開発者） | 最終的な設計判断と承認。差異の解決の最終判断 |
| Claude Code（主担当） | 設計の具体化、実装、リファクタリング、テストの実装 |
| Codex（独立検証担当） | 物理モデル・数式・数値計算・テストの妥当性の検証。原則として検証結果を報告し、実装コードを直接変更しない |

### 9.2 手順

1. **仕様の確定**（Claude Code が作成、人間が承認）：[05](05-physics-model.md) と本書に、前提条件・数式・期待する物理法則（保存則・対称性・極限・解析解）を定義する。
2. **Codex による独立導出**：実装コードとテストを見ずに、仕様だけから数式・解析解・境界条件・テストケースを導出し、検証資料として保存する（§9.3）。05 に書かれた式（閉形式や散逸量など）も、そのまま受け取らずに導出し直して確かめる。
3. **Claude Code による実装**：同じ仕様に基づいて実装とテスト（VER）を作る。独立性を保つため、原則として、照合が終わるまで Codex の導出結果を参照しない。
4. **Codex による照合**：実装・テストと独立導出の結果を比較し、数式、符号、単位、保存則、数値安定性などを検証する。差異を「一致／不一致／判断保留」に分類して報告する。
5. **差異の解決**：不一致は、物理法則・解析解・数値実験・実測データなどの**根拠**を用いて解決する。AI 同士の多数決や、どちらの AI の結果かでは判断しない。根拠で決着しない場合は人間が判断し、判断と理由を記録する。仕様の誤りなら 05・本書を、実装の誤りなら実装とテストを修正する（修正は Claude Code が行う）。設計上の重要な変更は ADR に残す。

手順 2 は実装と並行して進めてよい。手順 4 は対象機能の実装後に行う。

### 9.3 記録

- 置き場所（予定）：`verification/independent/IV-xx/`。実装側のテスト（`packages/physics-core/test/`）とは区別して管理する。
  - 導出資料（手順 2）、照合結果（手順 4）、差異の解決記録（手順 5）を分けて保存する。ファイル形式は未決定。
- 導出資料と照合結果には、各項目について**前提条件・期待値・許容誤差・根拠**を記録する。許容誤差は §3 の方針に従い、根拠のない数値を決め打ちしない。
- Codex が導出したテストケースを実行可能な形にして実装に対して実行するか、その場合に CI へ含めるかは未決定。含める場合も、実装側の VER テストとは別の場所・別の名前で管理する。

| IV-01 | 接触ソルバー（$\mathbf K$、反発、固着／滑り、無限質量モード、診断） | 05 §6.3〜6.12 | 符号、保存則、散逸量、閉形式、連成時の挙動 | 高 | M1.3 | 実施 |

### 9.5 注意

- Codex の初回検証（手順 2）は、Claude Code の実装を前提としない。
- **AI による検証結果は正しさの保証ではない。** 自動テスト（§4）、解析解、実測による妥当性確認（§5）と併用する。
- 独立導出と実装の両方が同じ仕様に基づくため、**仕様そのものの誤り**は両者に共通して現れうる。仕様の前提を疑う観点（次元解析、極限、対称性、物理的な直観との比較）も照合に含める。
