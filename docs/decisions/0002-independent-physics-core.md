# ADR-0002: 描画から独立した独自の Physics Core

- Status: Accepted (provisional)
- Date: 2026-10-18
- 関連：[04-architecture.md](../04-architecture.md)、[05-physics-model.md](../05-physics-model.md)

## Context

- 本プロジェクトの価値は、接触条件から初速・回転・軌道を物理的に計算し、その正しさを検証できることにある。
- 汎用の剛体物理エンジンは、多数の物体を安定かつ高速に扱うことを重視した設計が一般的であり、本プロジェクトが必要とする「1 回の衝突の条件と結果の対応」を、仮定を明示したまま制御・検証しにくい（個々のエンジンの接触モデルの詳細は未調査）。
- 将来、接触モデルを有限時間接触・面接触・関節拘束へ段階的に進化させたい。
- 描画（Three.js）を将来差し替える可能性、計算を Web Worker や WASM へ移す可能性がある。

## Decision

- 物理計算を `packages/physics-core`（KickDynamics Core、仮称）として、TypeScript で独自に実装する。
- Core は Three.js、DOM、WebGL、ブラウザ API、UI フレームワークに依存しない。ランタイム依存パッケージは原則ゼロとする。
- Core の API は素のデータを受け渡す純粋関数を基本とする（[04 §6、§9](../04-architecture.md)）。
- 接触モデルの中核（衝撃量の計算、固着／滑り、反発）を Rapier などの汎用剛体エンジンに委ねない。
- Rust/WASM への移行は決定しない。性能計測の結果をもとに別の ADR で判断する。

## Consequences

- 良い点：仮定と数式を 1 対 1 で対応させて実装・テストできる。描画と独立にテストできる。将来のモデル差し替えや WASM 化の境界が明確になる。
- 注意点：ベクトル・行列・四元数の演算や積分器を自前で実装し、テストする必要がある。Three.js 型との変換アダプタが必要になる。汎用エンジンが提供する機能（多物体の衝突判定など）は使えない。

## Alternatives

| 案 | 評価 |
|---|---|
| Rapier（WASM）、cannon-es、ammo.js などの汎用剛体エンジンに接触を委ねる | 衝突の仮定を制御・検証しにくい。不採用（将来、ゴールポストなど本質でない衝突に限って使う可能性は未決定） |
| Core で Three.js の `Vector3` 等を直接使う | 描画への依存が生じ、Node でのテストや WASM 化を妨げる。不採用 |
| 最初から Rust/WASM で実装する | 性能上の必要性が未確認で、開発・デバッグのコストが高い。現時点では不採用 |

## 見直し条件

- 性能計測で TypeScript 実装が要求を満たさない場合（Rust/WASM などを検討）
- Phase 4 以降で、関節拘束などに既存の多体動力学ライブラリの利用が妥当と判断された場合
