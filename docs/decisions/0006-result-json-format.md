# ADR-0006: 結果の出力形式（JSON 1 ファイル）

- Status: Accepted
- Date: 2026-10-20
- 関連：[04-architecture.md](../04-architecture.md) §6、[02-requirements.md](../02-requirements.md) FR-20・NFR-05・NFR-06、spec AC-14、[OQ-19](../research/references-and-open-questions.md)、tasks T1.5-06

## Context

- FR-20 は、入力・パラメータ・結果をファイルとして出力することを求める。形式は OQ-19 で未決定だった。
- AC-14 は、出力した入力・パラメータ・設定で Core を再実行すると同じ結果が得られることを求める（NFR-05 の決定性、NFR-06 の再現性）。
- パラメータは値だけでなく、単位・確からしさ・出典を持つ（05 §10）。多くが「仮置き」で、結果の解釈にはこの情報が欠かせない。
- 軌道は全ステップのサンプル（初期の入力で数千サンプル）を持つ。

## Decision

- **JSON 1 ファイル**で出力する（2026-10-20、人間が決定）。CSV は出力しない。
- 中身は、入力（`KickInput`）・パラメータ（`ParameterSet` をメタデータごと）・設定（`SimulationSettings`）・モデルの版・結果（衝突・測定値・警告・軌道の全サンプル）。単位は Core の内部単位（SI）のままで、`units: "SI"` を明記する。
- 最上位にスキーマ名 `kickdynamics-result` と版 `schemaVersion`（初版 1）を置く。形式を変えたら版を上げる（**暫定**：互換性の扱いと、古い版の読み込みは、読み込み機能を作るときに決める）。
- 軌道は `Trajectory` の各 `Float64Array` を数値の配列にし、`sampleCount` を加える。
- JSON は −0 を 0 として書くため、Lab は Core に渡す入力から −0 を除く（+0 にする）。出力した入力で再実行したときに、元と同じ計算になる。
- 実装は Lab（`apps/web/src/export/result-json.ts`）に置く。Core は出力形式に依存しない。

## Consequences

- 1 ファイルで再実行に必要なものがすべてそろい、AC-14 を往復テストで確かめられる。
- パラメータの確からしさ・出典が結果と一緒に残る。
- 数値は JavaScript の `JSON.stringify` の最短表現で書くため、倍精度の値は読み戻すと同じ値になる（−0 を除く。上記のとおり入力から除いている）。
- ファイルは大きめになる（初期の入力で約 1 MB、整形あり）。表計算ソフトでそのまま開けない。

## Alternatives

| 案 | 評価 |
|---|---|
| JSON ＋ 軌道の CSV | 表計算ソフトで軌道を見やすいが、ファイルが 2 つになり、整合の管理が増える。必要になってから追加する |
| CSV だけ | パラメータのメタデータや衝突の結果のような入れ子の構造を表しにくい。再実行に必要な情報を 1 つにまとめにくい |
| バイナリ形式 | 小さく速いが、人が読めず、依存の追加が必要になりうる（ADR-0004） |
