# ADR-0010: A1 の前にキック入力 UI を改善する（U1）

- Status: Accepted
- Date: 2026-11-21
- 関連：[03-roadmap.md](../03-roadmap.md) §3・§6、[specs/003-input-ui/spec.md](../../specs/003-input-ui/spec.md)、[R-13 の調査メモ](../research/r13-golf-game-shot-ui.md)、[ADR-0009](0009-plan-after-v1.md)、OQ-03

## Context

- Lab でキックの条件を変えて試すのに手間がかかる（ユーザーの観察、2026-11-21）。
  - 接触点を 3D のクリックで置くので、思った位置に置きにくい。
  - 足の移動方向を 2 本のスライダーで別々に動かす。
  - 足がボールから離れる向きの入力（矢印が赤）を選べてしまう。
  - 矢印の終点が接触点にあり、方向を「接触点から引っぱる」感覚と合わない。
- A1（空力の更新）と Phase 2 では、条件を変えて何度も蹴る作業が増える。
- R-13 の調査メモに、ゴルフゲームの操作の構造を借りた入力 UI の案（§6.3、すべて候補）がある。

## Decision

2026-11-21、人間が決定。

1. A1 の前に、UI だけの小さな段階 U1（仮称）を入れる。範囲と受入条件は spec 003。
2. 接触点はワールド座標に固定し、足の移動方向を変えても動かさない。方向は、3D ビューの中で接触点を根元とする矢印の先端と、接触点を中心とする回転ギズモ（方位・仰角のリング）で変える。
3. 接触点は、カメラの水平の向きからボールを水平に見た面（打点パッド、3D ビューの右下）でも指定できる。足の移動方向を変えても、3D でも 2D でも打点は動かない。足の後ろから見る視点（V キー）を設ける。
4. 足の移動方向から見た打点の中心からのずれを $h_{\max}$（暫定 0.95）以下に制限し、方向の操作はその範囲の端で止める。足が離れる向きの入力は作れない。
5. 既存のスライダーは数値入力として残す。

## Consequences

- Core と `KickInput` は変わらない。`MODEL_VERSION` は変えず、独立検証（06 §9）は行わない。
- UI の成熟度は UM-2 のまま（操作性の改善）。
- OQ-03 の UI 表現（暫定）を更新する。
- 速度の矢印の長さは足の速さに比例させず、一定にする（ハンドルとして掴むため）。速さは数値で示す。
- A1 の着手が U1 の分だけ遅れる。
- Phase 2 で脚のモデルを入れると、足の速度の入れ方が変わる可能性がある。方向ハンドルは作り直しになりうる。

## Alternatives

| 案 | 評価 |
|---|---|
| A1 の後に回す | A1 の軌道の比較で、条件を変えて試す手間がそのまま残る |
| 接触点を足の向きに追従させる（打点 $(a, b)$ を保つ） | 画面イメージ（2026-11-21）で確認したが、「接触点を固定して矢印の先を動かす」というユーザーの操作のイメージと合わなかった |
| 方向を 2D の方向パッド（右下）で操作する | 同じく画面イメージで確認し、3D ワールドの中で角度を動かす円弧のほうが直感的とされた |
