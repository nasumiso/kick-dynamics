# 003 キック入力 UI の改善（U1、仮称）仕様

> 状態：完了（2026-11-22、U1-04）。承認（2026-11-21、人間、U0-01。画面イメージの確認により §3・§4 を改訂してから承認）。実装中のユーザーの確認により §3・§4 を改訂した（打点パッドの視点、回転ギズモ、足の後ろからの視点。tasks U1-03 の結果欄）。本書は U1（[03 §3](../../docs/03-roadmap.md)）の範囲と受入条件（AC-U）の正本です。
> 数式・座標系・キック入力の定義は [05](../../docs/05-physics-model.md)（§6.2、§9）、Phase 1 の入力範囲と初期値は [001 spec §4](../001-kick-prototype/spec.md) を正本とし、本書には複製しません。位置づけは [ADR-0010](../../docs/decisions/0010-input-ui-before-a1.md)。

## 1. 目的

Lab でキックの条件を変えて試す手間を減らす。具体的には次の 3 点。

1. 接触点を、3D のクリックだけでなく、2D の「ボールの面」（打点パッド）の上で指定できるようにする。
2. 足の移動方向（方位角 ψ・仰角 θ）を、3D ビューの中の回転ギズモ（リング）と矢印の先端のドラッグで変えられるようにする。
3. 足がボールから離れる向き（$\mathbf v_A^p\cdot\mathbf n \le 0$、05 §6.2）の入力を、これらの操作では作れないようにする。

参考：[R-13 の調査メモ](../../docs/research/r13-golf-game-shot-ui.md) §6.3 の案 B。ゲームの画面は複製しない。

## 2. 範囲

- 含む：`apps/web` の入力 UI（打点パッド、3D の方向ハンドル）、3D の速度の矢印の描き方、3D クリックの扱い、数値入力との同期。
- 含まない：
  - Core（`packages/physics-core`）の変更。`KickInput` の定義は変えない。
  - パワーゲージ・タイミングによるぶれ（R-13 案 C・D）などのゲーム的な操作。
  - 足の速さ・$\phi$・$(s_x, s_y)$・$\boldsymbol\omega_A$ の操作方法の変更（既存のスライダーのまま）。
  - UI コントロール用ライブラリの導入（OQ-17）。

## 3. 打点と方向の関係

- 接触点 $\mathbf d$ はワールド座標で持つ（Phase 1 と同じ）。**足の移動方向を変えても接触点は動かない**。
- 足の移動方向の単位ベクトルを $\mathbf f$（$\mathbf v_A^p$ の向き。ψ・θ から 001 spec §4 の定義で求める）とする。
- **入力の範囲（打点の制限）**：足の移動方向 $\mathbf f$ に沿ってボールを見たときの、接触点の中心からのずれ（半径で割った値）が $h_{\max}$ 以下。言いかえると $\mathbf d\cdot\mathbf f \le -\sqrt{1 - h_{\max}^2}$（$\mathbf f$ と $\mathbf n = -\mathbf d$ のなす角が $\arcsin h_{\max}$ 以下）。このとき $\mathbf v_A^p\cdot\mathbf n > 0$ が常に成り立つ。方向の操作は、この範囲の端で止まる（§4）。
- **打点パッドの座標の組**（2026-11-21 改訂、ユーザーの指示「ボールを水平にみたときの打点」「3D で打点は動かないのだから 2D でも動かない」）：**カメラの水平の向き** $\mathbf h = (\cos\psi_c, 0, \sin\psi_c)$（$\psi_c$ はカメラから注視点への向きの方位角）からボールを水平に見る。右 $\mathbf r = (-\sin\psi_c, 0, \cos\psi_c)$、上 $\mathbf u = \hat{\mathbf y}$。足の移動方向を変えてもパッドの打点は動かず、カメラを回すとパッドの見え方が変わる。足の後ろから見る視点（§4）では $\psi_c = \psi$。
- 打点 $(a, b) = (\mathbf d\cdot\mathbf r,\ \mathbf d\cdot\hat{\mathbf y})$。逆に、パッドで $(a, b)$ を選んだときは $\mathbf d = a\,\mathbf r + b\,\hat{\mathbf y} - \sqrt{1 - a^2 - b^2}\,\mathbf h$（カメラの側の半球）とする。接触点がボールの裏側（$\mathbf d\cdot\mathbf h > 0$）にあるときは、投影した位置を白抜きで示す。
- パッドで選べるのは、パッドの縁（$\sqrt{a^2+b^2} \le 0.99$、表示の値）の内側で、今の $\mathbf f$ に対して入力の範囲内の部分。形は θ・ψ・カメラの向きで変わるので、画素ごとに判定して外側を灰色にする。外側を選んだときは、今の打点から選んだ点へ進んで範囲の端で止める（今の打点が裏側なら、最も近い選べる点にする。カメラが足の前にあると選べる点がないことがあり、そのときは何もしない）。

範囲と初期値（暫定、UI の試作用の値で、物理的な根拠・出典はない）：

| 量 | 値 | 備考 |
|---|---|---|
| $h_{\max}$ | 0.95（$\arcsin 0.95 \approx 71.8°$） | ボールをかすめる当たり方を避けるための値 |
| 初期値 | 001 spec §4 のまま（$\mathbf d = -\hat{\mathbf x}$、ψ = 0°、θ = 10°） | 既定のカメラでは、打点はパッドの左寄り。足の後ろから見る視点では中心 $(0, 0)$ |

## 4. 画面と操作

| 部品 | 置き場所 | 操作 | 表示 |
|---|---|---|---|
| 打点パッド | 3D ビューの右下に重ねる | ドラッグ・クリック・矢印キー（Shift で細かく） | カメラの水平の向きから見たボールの円、選べない部分（灰色）、打点のカーソル、中心からのずれ（mm）。回転量は表示しない（回転は Core の計算の結果としてだけ示す） |
| 速度の矢印 | 3D ビュー | 先端の球をドラッグすると、先端がマウスに付いてくるように ψ・θ を同時に変える | 根元を接触点に置き、$\mathbf f$ の向きに一定の長さ（表示専用）で伸ばす。ボールに隠れないよう手前に描く |
| 回転ギズモ：方位のリング | 3D ビュー | 掴んでドラッグすると ψ だけを変える。回転量は、マウスの動きのうち掴んだ点でのリングの接線方向（画面上）の成分を、リングの画面上の半径で割った値（rad） | 接触点を中心とする水平の大円。画面上で一定の大きさ。リングは動かず、今の ψ の位置の目印がリングに沿って動く |
| 回転ギズモ：仰角のリング | 3D ビュー | 同じ方式で θ だけを変える | 接触点を中心とし、矢印を含む鉛直の面の大円（ψ を変えると軸ごと回る）。目印は今の θ の位置 |
| 足の後ろから見る視点（2026-11-21 追加） | 表示パネルのボタン、V キー | 押すと、カメラを足の移動方向の水平成分の真後ろ・上に置き、飛ぶ向きを見る（ゴルフゲームのショットの視点）。その後は通常どおりカメラを操作できる | 配置はボールの後ろ 1.4 m・上 0.5 m（表示の値、暫定）。注視点（カメラの回転の中心）はボールの中心 |
| 数値入力（既存のスライダー） | 右パネル | 既存のとおり | ハンドル・パッドと値を同期する |
| 3D のクリック（ボール） | 3D ビュー | 既存のとおり | 今の $\mathbf f$ で範囲内なら、そのまま接触点にする。範囲外なら、接触点を優先し、$\mathbf f$ を範囲内の最も近い向きへ寄せ、その旨を表示する |

- 方向の操作（ハンドル・数値入力）で範囲外の向きを求めたときは、今の向きから求めた向きへ動かしていって、範囲の端で止める。
- ギズモを掴んでいる間は、カメラ操作をしない。掴んだリング・球は黄色に、掴んでいないリングは薄くする。
- リングは、回すとその位置へ来る向きが範囲外の部分を灰色で描く。
- 矢印の長さ、円弧の太さ、パッドの大きさなどの細かい値は試作で決める（暫定、表示専用）。

## 5. 受入条件

| ID | 条件 | 確認方法 |
|---|---|---|
| AC-U01 | 打点パッドの操作で、接触点マーカー・足・速度の矢印が 3D ビューで追従する | 手動 |
| AC-U02 | 打点パッドで選べるすべての $(a, b)$ で $\mathbf v_A^p\cdot\mathbf n > 0$ になる。範囲外を選ぶと範囲の端に寄る | 自動（格子点での判定） |
| AC-U03 | $(a, b) \to \mathbf d \to (a, b)$ の往復が一致する。足の後ろから見る視点で、初期の状態の打点がパッドの中心になる。足の移動方向を変えてもパッドの打点は動かない | 自動 |
| AC-U04 | 回転ギズモ（リング・矢印の先端）のドラッグで ψ・θ が変わり、接触点は動かない。範囲外へは動かず、端で止まる | 自動（方向の制限の関数）＋ 手動 |
| AC-U05 | ハンドル・パッドと数値入力のどちらで変えても、両者の表示が一致する | 手動 |
| AC-U06 | 範囲外の向きになる 3D クリックでは、接触点はクリックした点になり、$\mathbf f$ が範囲内に寄せられ、その旨が表示される | 自動（寄せる関数）＋ 手動 |
| AC-U07 | 同じ $\mathbf d$・$\mathbf v_A^p$ を Core に渡したとき、結果が変更の前と同じ（初期の状態で、既存の run-kick・result-json のテストが変わらず合格） | 自動 |
| AC-U08 | Core に変更がなく、`npm run check` に合格する | 自動 |
